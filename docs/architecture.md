# Architecture and design decisions

## Reproducibility

- Fixed random seeds in data generation, train/test split and candidate estimator.
- All preprocessing is inside a scikit-learn `Pipeline`/`ColumnTransformer`, so training and inference apply the same transformations.
- MLflow logs run parameters, selected metrics and model artifacts; the local registry uses a SQLite backend store.
- A model signature and input example are recorded for the selected model.
- The CI workflow trains from scratch before running the tests.

## Monitoring

The input monitor compares each current feature against a frozen training-reference sample. Numeric features are binned by quantiles of the reference sample. Categorical PSI is computed over the union of observed categories. The monitor records per-feature PSI and flags values above the configurable threshold.

This is not a substitute for monitoring target/label shift, model performance or service health. A production service should log prediction inputs/outputs subject to privacy controls, latency, failures, model version and delayed ground-truth outcomes. Retraining should be triggered through an explicit, evaluated and approved workflow, never solely because one PSI value crosses a heuristic threshold.

## Serving

FastAPI loads the local MLflow model artifact generated by the training command. `/predict` validates feature types/ranges and returns the positive-class probability. `/health` distinguishes an available API process from the model artifact being present.

## GenAI and MCP

The retriever indexes local Markdown documents in-memory with TF-IDF. The assistant offers two tools: one for model inference and one for reading the latest drift report. With `OPENAI_API_KEY`, an OpenAI-compatible Chat Completions API can decide when to invoke them. Without credentials, deterministic mode demonstrates retrieval and direct tool routing. `mcp_server.py` exposes these operations over MCP stdio for an MCP-compatible client.

## Known limitations

- Synthetic data has no external validity.
- The train/test split is random, not temporal.
- No automatic retraining, canary deployment, rollback policy, online feature store, or full service telemetry.
- PSI is a simple input-distribution metric, not a performance metric.
- The local model registry and notebook-based Databricks experiment are distinct tracking environments.
- Cloud endpoint creation is a manual optional step because workspace availability, permissions and quotas vary.
